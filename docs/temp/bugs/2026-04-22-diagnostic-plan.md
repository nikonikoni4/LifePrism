# 删除后输入框失效问题 - 诊断计划

## 问题现象

1. **触发条件**：在打包环境下，删除 Timeline 的 custom block 或 DataReview 的 log 后
2. **症状**：所有输入框无法输入
3. **恢复方法**：关闭窗口，从系统托盘重新打开窗口后恢复
4. **环境特性**：仅在打包环境下出现，开发环境正常

## 已建立的假设

### 假设1: confirm()对话框创建了自己的遮罩层
**描述**：打包环境下，Electron可能为confirm()对话框添加了额外的遮罩层，且该遮罩层在confirm关闭后未被清理。

**验证方法**：查看日志中"confirm后"的遮罩层详情，对比"删除前"的遮罩层。

**关键日志**：
- `[Popover] 删除前 - 遮罩层详情`
- `[Popover] confirm后 - 遮罩层详情`

### 假设2: React组件卸载时机问题
**描述**：打包环境下，confirm()阻塞导致React的卸载被延迟，Popover的遮罩层DOM元素未被移除。

**验证方法**：查看isOpen变化和组件卸载的日志时序。

**关键日志**：
- `[Popover] isOpen 变化: false`
- `[Popover] isOpen=false 100ms后，遮罩层数量`
- `[Popover] 组件卸载`

### 假设3: 事件监听器未清理
**描述**：useEffect的清理函数在打包环境下未正确执行，导致点击外部关闭的事件监听器残留，拦截了所有点击事件。

**验证方法**：查看组件卸载日志，检查清理函数是否执行。

**关键日志**：
- `[Popover] 组件卸载`
- `[Popover] 卸载时遮罩层数量`

### 假设4: 遮罩层来自其他组件
**描述**：遮罩层可能来自其他打开的模态框或弹窗（如批量分类修改弹窗），而不是CustomBlockPopover。

**验证方法**：查看遮罩层的className，判断来源。

**关键日志**：
- 遮罩层的 `className` 字段
- CustomBlockPopover的遮罩层：`bg-black/20 z-[999]`
- DataReview批量修改的遮罩层：`bg-black/50 z-50`

### 假设5: z-index层叠问题
**描述**：遮罩层的z-index过高，覆盖在所有元素之上，即使Popover已关闭。

**验证方法**：查看遮罩层的zIndex值。

**关键日志**：
- 遮罩层的 `zIndex` 字段

### 假设6: 窗口隐藏/显示导致的状态不一致（新增）
**描述**：基于"关闭窗口再打开后恢复"的现象，可能是窗口隐藏时某些状态未正确保存，重新显示时触发了重新渲染，清理了残留的DOM。

**验证方法**：对比窗口隐藏前后的DOM状态。

**关键日志**：
- Electron主进程的窗口事件日志（hide/show）

## 测试步骤

### 测试1: Timeline删除Custom Block

1. 打开打包后的应用
2. 进入 LifeWatch → Timeline
3. 创建一个 custom block
4. 点击该 block 打开编辑弹窗
5. 点击删除按钮
6. 在confirm对话框中点击"确定"
7. 尝试在任意输入框输入内容
8. **记录现象**：是否能输入？

### 测试2: DataReview删除Log

1. 打开打包后的应用
2. 进入 LifeWatch → Category → Data Review
3. 点击某条记录的删除按钮
4. 在confirm对话框中点击"确定"
5. 尝试在任意输入框输入内容
6. **记录现象**：是否能输入？

### 测试3: 窗口隐藏/显示恢复

1. 复现问题（执行测试1或测试2）
2. 点击窗口关闭按钮（隐藏到托盘）
3. 从系统托盘点击图标重新打开窗口
4. 尝试在任意输入框输入内容
5. **记录现象**：是否恢复正常？

## 日志收集

### 日志位置
`localData/debug_logs/electron.log`

### 关键日志标记
- `[Popover]` - CustomBlockPopover组件的日志
- `[CustomBlockLayer]` - CustomBlockLayer组件的日志
- `[DataReview]` - DataReviewTab组件的日志

### 日志分析重点

1. **遮罩层数量变化**：
   - 删除前有几个遮罩层？
   - confirm后有几个遮罩层？
   - 删除完成500ms后有几个遮罩层？

2. **遮罩层来源**：
   - 查看className，判断是哪个组件的遮罩层
   - `bg-black/20` → CustomBlockPopover
   - `bg-black/50` → DataReview批量修改弹窗

3. **组件生命周期**：
   - isOpen何时变为false？
   - 组件是否真的卸载了？
   - 卸载时遮罩层是否还存在？

4. **confirm对话框的影响**：
   - confirm显示前后，遮罩层是否有变化？
   - confirm耗时多久？

## 预期结果

根据日志，我们应该能够确定：
1. 遮罩层的确切来源（哪个组件）
2. 遮罩层为什么没有被清理（React未卸载？DOM未移除？）
3. 为什么关闭窗口再打开能恢复（窗口重新渲染？状态重置？）

## 下一步

收集完整日志后，根据日志分析结果，制定精确的修复方案。
