# 「What Am I Doing？」创意总结

> 记录时间：2026-07-02
> 类型：产品创意 / 临时文档

---

## 一、创意名称和介绍

**创意名称：What Am I Doing？（简称 WAID）**

**产品形态：** 一款桌面级原生应用（Desktop App），以「置顶浮窗」作为核心交互入口，常驻在桌面最前层。

**想解决的问题：** 在 AI 辅助工作的时代，用户越来越频繁地面临多分支、多任务并行的场景。一个任务启动后，中途可能被 AI 给出新思路带偏、被临时插入的任务打断、或者自己在探索中陷入局部细节而忘记了最初要做什么。WAID 要解决的就是这个「初始目标丢失」的问题。

**想做的原因：** 现有的 Todo List、番茄钟、笔记工具都只能记录「任务名称」和「完成状态」，无法捕捉任务**执行过程中**的思考分支、决策节点、中途切换等关键过程信息。用户在一天结束后想复盘时，往往已经忘记了当时的思考路径——"我明明是要做 A 的，怎么最后做成了 B？"WAID 填补的就是这部分「过程记录」的空白。

**核心功能：**
1. **置顶弹窗** — 可弹出始终置顶的悬浮窗口，用户可以在此快速添加当前任务。
2. **过程记录** — 自动计时，用户可在执行过程中随时标记关键节点（想法分支、决策点、中断切换等）。
3. **结果总结** — 任务完成（或结束计时）后，自动生成一份简洁的过程总结，串联任务执行的时间线。

## 二、现有工具的不足：为什么 Todo List 不够用

WAID 的诞生并非凭空想象，而是源于对现有任务管理工具在 AI 协作场景下**结构性缺陷**的观察。以下是三个核心问题。

### 2.1 任务步骤与依赖关系不明确

在开始写 Todo List 时，目标往往还不够清晰。表面上一个任务（如"修复登录模块的 token 刷新 bug"），实际包含多个子步骤：

```
A1: 复现 bug → A2: 定位原因 → A3: 修复并验证
```

但传统的 Todo List 是**扁平的**——它只能把 A1、A2、A3 并列列出，丢失了父子层级和执行顺序。

更关键的是，子任务之间存在不同类型的**依赖关系**：

| 依赖类型 | 说明 | 示例 |
|---------|------|------|
| **阻塞型** | 必须完成当前任务才能进行下一步 | 不修好 token 刷新，就无法验证后续的接口调用 |
| **非阻塞型** | 优化或可选项，不阻碍主任务完成 | "顺便把那个变量的命名也改一下"——做了更好，不做也不影响 |
| **前置任务** | 需要先完成其他任务才能开始当前任务 | 修复 token 刷新之前，需要先看懂认证模块的整体流程（而看懂流程本身又可能需要先阅读相关文档……） |

前置任务尤其容易形成**链式依赖**：B 是 A 的前置 → C 是 B 的前置 → ……最终用户发现自己离最初的目标越来越远，甚至忘记了为什么要做这些前置工作。

### 2.2 AI 时代的多任务并行混乱

在 AI 辅助工作的时代，我们经常同时与多个 Agent 交互。当你向一个 Agent 发起任务后需要等待结果时，你不会干等着——你会去开启另一个任务。这种模式本身是高效的，但缺乏管理就会陷入混乱：

```
启动任务 A → 等待 Agent 返回结果
    ↓ （等待期间）
启动任务 B → 任务 B 遇到阻塞，需要先做前置任务
    ↓
转去做任务 C → 任务 C 又引出新的想法……
    ↓
？？？最初想做什么来着？
```

这是一条典型的**目标漂移链**：每次切换在当时看来都是合理的（等结果、遇到阻塞、新想法有价值），但串联起来就变成了一条没有回程的路。核心矛盾在于：**并行 ≠ 有序**，Task Switch 的成本被严重低估——不仅有显性的"切回去要重新加载上下文"，还有隐性的"切太多后干脆忘了要切回去"。

### 2.3 记录思维链与优先级管理

在频繁的任务切换中，有三个问题是持续需要回答的：

1. **为什么要跳转？** — 是主动决策（"这个前置任务必须先做"）还是被动反应（"这个看起来有意思，点开看看"）？不记录跳转原因，事后就无法区分"必要的切换"和"无意识的跑偏"。

2. **跳转的任务必须现在做吗？** — 紧急 ≠ 重要。AI 给出的新思路可能很有价值，但不一定需要**立即**跟进。很多时候只需要**先记下来**，完成手头任务后再处理。

3. **非阻塞子任务只需记录，不需立即执行** — 执行过程中冒出的优化想法、后续可探索的分支，应该被"捕获"而不是被"执行"。捕获意味着留痕、可追溯、不会丢失；执行意味着切换上下文、分散注意力。

这三点指向同一个核心能力——**"要事第一"的持续自我提醒**。在 AI 能产出无限可能性的时代，人类的瓶颈不是"想不到"，而是"守不住"。知道自己在做什么、为什么在做、接下来应该回到哪里——这本身就是一种被严重低估的生产力。

## 三、目标用户及痛点

**目标用户：**
- AI 工具重度使用者（程序员、研究者、内容创作者等），每天频繁与 AI 交互，容易在多轮对话中偏离原始目标。
- 需要深度专注的知识工作者，一天内需要切换多个复杂度较高的任务。
- 有复盘习惯的人——写日记、做周回顾、希望持续改进自己工作方式的人。

**使用场景：**
- 打开 WAID 置顶浮窗 → 输入当前要做的事（如「修复登录模块的 token 刷新 bug」）
- 在 AI 对话或编码过程中，每当发现一个新方向或临时想法，在浮窗中快速打一个节点（如「发现可能是 cookie 问题」「临时去查了跨域配置」）
- 任务完成后，WAID 生成一条时间线总结，用户可以在当天写日记时回顾：今天做了什么、中间跑了多少次题、哪些分支值得后续跟进。

**用户痛点：**
1. **注意力稀释** — 在 AI 多分支、多任务并行场景下，用户容易忘记自己最初的目标是什么。
2. **记录缺失** — 现有 Todo List 只记录起止状态，无法完整记录执行过程中的想法节点和探索分支。
3. **容易跑偏** — 执行中容易陷入局部细节、被 AI 带偏方向、或者不自觉切换到其他任务，导致原任务效率降低或完成度不佳。

## 四、创意价值与意义

**效率提升：**
WAID 的「聚焦提醒」机制让用户在跑偏时能快速看到自己最初写下的任务目标，像一个温和的旁观者在说"嘿，你本来是要做什么来着？"——帮助用户主动拉回正轨，减少无意识的时间浪费。

**辅助个人复盘：**
每个人的成长离不开对过去的回顾。WAID 记录的不仅是「做了什么」，更是「怎么做的」——思考路径、决策分支、中断次数。这些数据是写日记、做周回顾时的宝贵素材。用户可以清晰看到：今天哪些任务高效完成、哪些任务反复跑偏、自己的注意力模式是怎样的。

**个人行动日志：**
长期使用后，WAID 积累的数据构成了一部「个人行动日志」——从宏观上反映用户的工作习惯、效率趋势和思维模式，为持续自我改进提供数据支撑。

**社会价值：**
在 AI 工具日益渗透工作的时代，人类面临的核心挑战不再是「找不到信息」，而是「在信息洪流和无限可能性中保持方向」。WAID 本质上是一个「锚点工具」——它帮助人与 AI 协作时始终保持对自身目标的觉知，让 AI 成为辅助而非干扰，促进更健康的人机协作关系。
