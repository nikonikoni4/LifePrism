## 权限设置概要

| 页面      | 增   | 删   | 改   | 查   |
| --------- | :--- | ---- | ---- | ---- |
| planDoc   | ✅    | ✅    | ✅    | ✅    |
| taskpool  | ❌    | ✅    | ✅    | ✅    |
| calendar  | ❌    | ❌    | ✅    | ✅    |
| dailyView | ✅    | ✅    | ✅    | ✅    |

1. 为什么不给taskpool和calendar增加 “增加”权限：taskpool和calendar视图的作用是安排计划，没有增加的权力。
2. 为什么taskpool可以删除和修改？：因为在安排的时候若有不合适，在返回md修改导致操作步骤增多，所有需要支持taskpool的删除和修改权限



### 一、planDoc的增删改查过程

planDoc的所有增删改查都是通过在todoblock位置进行，需要通过 “保存”->"同步"才能进行更新。md的更新过程是：taskpool点击同步，后端读取md文档，解析代码块。

**具体过程**：前端修改->点击保存->后端将数据保存在md文档中。这里不涉及数据库操作，只有点击任务池界面的“同步”涉及数据库操作之后，才会解析md文档，先增加锚点（若没有的话），然后提取基本信息，构建todo，然后再和数据库进行增删改查。

**注意**：md文档删除todo之后，在后续进行**同步时**需要弹出一个对话框让用户确认是否删除此任务

### 二、taskpool的删改查

**具体过程：** task修改删除内容->后端数据库修改->md文档对应锚点修改->前端涉及到的这四个页面的数据更新

**注意**：当点击**删除时**，需要弹出一个对话框确认是否删除内容

###  三、calendar的修改

具体过程：将taskpool拖拽到具体日期之后，修改todo的 状态和开始时间等内容内容

### 四、dailyView的增删改查

**具体过程**：前端操作->后端数据库更新->md文档（如果涉及到有plan_doc_id的todo时需要更新）->前端四个界面数据更新

**注意**：

- 当在有plan_doc_id的todo项增加子项时，改子项需要**继承这些属性**，并且**在添加时需要同时生成锚点id**，在md文档中找到父级位置，
- 增加时只能增加plandoc的子项，在最上方的输入框增加的内容不包括plan_doc_id

## 数据流说明

将planDoc与其他三个页面分为md数据源和数据库数据源。

1. md数据源 -> 数据库数据源:  通过taskpool的同步按钮进行同步。为什么要增加同步按钮？因为plandoc通常是思考过程，可能涉及到多处删改，所以需要增加手动按钮。
2. 数据库数据源->md数据源：会直接同步到md文档。
3. 删除内容说明：
   1. 在md文档中删除，点击同步时需要弹出删除提示
   2. 在taskpool中删除，弹出删除提示
   3. 在dailyview中删除，弹出删除提示



### 边界情况讨论

1. md数据源->数据库数据源：不存在边界情况，若没有内容则添加，多余内容则提示删除

2. 数据库数据源->md数据源：

   确认影响因素：source_anchor_id，parent_id, plan_doc_id

   正确情况下，一个todo的四个id存在，那么应该1）计划书存在 2）父todo存在 3）md文档中的锚点存在。
