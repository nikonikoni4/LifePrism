
# 页面遮挡问题解决说明

## 1. 问题现象
在应用的主页（Home）可以正常打开和查看 "指南 (User Guide)" 弹窗。但是，当进入 Mood、Journal 或 Being 等子页面后，点击指南按钮，虽然代码逻辑执行了，但屏幕上没有显示指南弹窗，或者看起来指南弹窗“跑到了页面下面”。

## 2. 根本原因：层叠上下文 (Stacking Context)

这是由 CSS 的层叠逻辑和 DOM 渲染顺序共同导致的。

1.  **DOM 结构顺序**：
    在 `App.tsx` 中，组件的渲染顺序如下：
    ```tsx
    // 1. 指南组件
    <UniversalGuide isOpen={showGuide} ... /> 
    
    // 2. 子页面容器
    <AnimatePresence>
       {currentView === 'mood' && <motion.div ... />}
    </AnimatePresence>
    ```

2.  **Z-Index 冲突**：
    *   `UniversalGuide` 之前设置了 `z-index: 100`。
    *   子页面（如 MoodView）的容器也设置了 `z-index: 100` 并且是全屏固定定位 (`fixed inset-0`)。

3.  **覆盖规则**：
    当两个定位元素拥有**相同**的 `z-index` 时，HTML 中**后出现**的元素会覆盖**先出现**的元素。
    因此，子页面（后渲染）像一张巨大的画布，盖住了先渲染的指南弹窗。

## 3. 解决方案：React Portal (传送门)

为了彻底解决这个问题，并避免未来新增页面再次出现类似的层级管理混乱，采用了 **React Portal** 技术。

### 技术原理
`createPortal` 允许将子节点渲染到存在于父组件 DOM 层次结构之外的 DOM 节点。

### 具体实施
我们修改了 `UniversalGuide.tsx`，不再将其直接渲染在 `App` 组件的节点树内部，而是直接挂载到 HTML 的 `<body>` 标签上。

```typescript
// 修改前
return (
  <motion.div className="fixed inset-0 z-[100] ..."> ... </motion.div>
)

// 修改后
import { createPortal } from 'react-dom';

return createPortal(
  <motion.div className="fixed inset-0 z-[9999] ..."> ... </motion.div>,
  document.body // 目标节点
);
```

### 达到的效果
1.  **脱离父级层叠限制**：指南弹窗现在物理层面上位于 `div#root` 之外，直接附着在 `body` 的最末端。
2.  **绝对顶层**：配合提升后的 `z-index: 9999`，无论应用内部的子页面（Mood, Journal）层级如何变化，指南弹窗永远漂浮在所有内容之上。
3.  **无需修改业务代码**：不需要调整 `App.tsx` 中的渲染顺序或所有子页面的 z-index，这是一种更健壮、低耦合的修复方式。
