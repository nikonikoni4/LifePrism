# 重构目标界面


## 界面重构

### 设计理念：工作流驱动的双栏布局

整个目标管理系统遵循 **承诺 → 目标 → 计划书 → 任务池 → 每日任务** 的工作流程。
UI设计应该体现这个流程的连贯性，让用户能够**无缝地**从一个阶段切换到下一个阶段。

### 布局模式

#### 模式一：双栏布局（默认/推荐）

双栏布局强调**上下文关联**，左右两个面板始终显示相邻的工作阶段：

| 视图组合 | 左侧面板 | 右侧面板 | 交互说明 |
|----------|----------|----------|----------|
| **组合1** | 目标列表 | 计划书 | 点击左侧目标 → 右侧显示该目标的计划书列表/编辑器 |
| **组合2** | 计划书 | 任务池 | 编辑计划书 → 点击同步按钮 → 任务同步到右侧任务池 |
| **组合3** | 任务池 | 日历/日期表 | 从左侧拖拽任务 → 放到右侧日期格子中进行安排 |
| **组合4** | 日历/日期表 | 每日任务 | 点击左侧日期 → 右侧显示该日的任务详情 |

**切换方式**：
- 点击顶部胶囊中的标签
- 点击左右切换按钮 `◀` `▶`

#### 模式二：单栏布局（可选）

对于小屏幕或用户偏好，可切换到单栏模式：
- 只显示一个面板
- 通过胶囊导航在不同视图间切换

#### 注意：
- 在单栏界面下，显示是直接加载目标页面，在双栏情况下水加载goalView/components/combinations对应的界面
```
┌──────────────────────┐
│  [单栏] [双栏]  切换   │
└──────────────────────┘
```

### TodoItem 统一数据模型

不使用继承，所有Todo使用统一模型，通过字段区分用途：

```python
class TodoItem:
    # === 基础属性 ===
    id: int                              # 唯一ID
    content: str                         # 任务内容
    parent_id: Optional[int]             # 父任务ID（支持无限层级嵌套）
    goal_id: Optional[str]               # 关联的Goal ID
    plan_doc_id: Optional[int]           # 来源计划书ID
    
    # === 来源追踪（用于MD同步） ===
    source_type: str                     # 'manual' | 'plan_doc'
    source_anchor_id: Optional[str]      # MD中的锚点ID（格式: lp:xxxxxx）
    
    # === 状态管理 ===
    state: str                           # 'pool' | 'scheduled' | 'completed' | 'shelved'
    scheduled_date: Optional[str]        # 安排到某天的日期 (YYYY-MM-DD)
    
    # === 时间相关 ===
    expected_finish_at: Optional[str]    # 预计完成日期
    actual_finish_at: Optional[str]      # 实际完成日期
    delay_days: Optional[int]            # 拖延天数 (actual - expected)
    delay_reason: Optional[str]          # 拖延/未完成原因
    
    # === 显示属性 ===
    color: str = "#FFFFFF"
    order_index: int                     # 每日列表排序
    pool_order_index: Optional[int]      # 任务池排序
    
    # === 嵌套展示（非持久化） ===
    children: Optional[List["TodoItem"]] = None
```

### 状态流转设计

```
                         schedule (安排日期)
┌────────────┐  ────────────────────────────►  ┌─────────────┐
│    pool    │                                  │  scheduled  │
│  (任务池中) │  ◄────────────────────────────  │ (已安排日期) │
└────────────┘         unschedule (取消安排)    └─────────────┘
      │                                               │
      │ shelve                              complete  │
      ▼                                               ▼
┌────────────┐                              ┌─────────────┐
│   shelved  │                              │  completed  │
│   (搁置)   │                              │  (已完成)    │
└────────────┘                              └─────────────┘

关键规则：
1. 父任务状态变化时(scheduled/shelved)，子任务自动跟随
2. 父任务完成与子任务完成相互独立，无强制关联
3. 计划书搁置时，其下所有未完成Todo自动变为搁置状态
```

### 任务池视图展示规则

- 显示 `state='pool'` 的任务
- **也显示** `state='scheduled'` 的任务，但用**不同样式**区分（如半透明、标签等）
- 支持嵌套展示：拖动父任务时，子任务跟随

### MD文档同步机制

#### 锚点格式（HTML注释，渲染时不可见）

```markdown
- [ ] 学习React基础 <!-- lp:a1b2c3d4 -->
  - [ ] 完成官方教程 <!-- lp:e5f6g7h8 -->
  - [ ] 做一个小项目 <!-- lp:i9j0k1l2 -->
- [x] 阅读CSAPP <!-- lp:m3n4o5p6 -->
```

#### 同步时机

| 操作 | 行为 |
|------|------|
| **打开计划书页面** | 自动扫描MD，同步到数据库（新增/更新/检测orphan） |
| **关闭计划书页面** | 自动将数据库状态回写到MD（更新 [ ] ↔ [x]） |
| **编辑MD内容时** | 手动触发同步按钮 |

#### 扫描流程（MD → 数据库）

```
1. 解析MD中所有 - [ ] 和 - [x] 项
2. 检查是否有锚点ID：
   - 有锚点：根据锚点ID匹配数据库记录，更新内容
   - 无锚点：生成新锚点ID，创建新TodoItem，回写锚点到MD
3. 数据库中有锚点但MD中找不到：标记为 orphan（可选：提示用户处理）
```

#### 回写流程（数据库 → MD）

```
1. 读取整个MD文件内容
2. 遍历数据库中该计划书的所有Todo
3. 根据锚点ID定位MD中的位置
4. 更新 [ ] ↔ [x] 状态
5. 写回文件
```

### 级联行为规则

| 触发 | 影响范围 | 行为 |
|------|----------|------|
| Goal 搁置 | Goal → PlanDoc → Todo | **待定**：是否级联搁置 |
| PlanDoc 搁置 | PlanDoc → Todo | 所有未完成Todo自动变为搁置 |
| 父Todo 安排日期 | 父Todo → 子Todo | 子任务跟随变为 scheduled 状态 |
| 父Todo 搁置 | 父Todo → 子Todo | 子任务跟随变为 shelved 状态 |
| 父Todo 完成 | 父Todo → 子Todo | **无影响**，子任务状态独立 |
| 子Todo 完成 | 子Todo → 父Todo | **无影响**，父任务状态独立 |

### 多层级任务展示规则

#### 设计原则

数据库采用**邻接表模型**（`parent_id` 指向父任务），多层级结构在**应用层构建**而非数据库递归查询。所有界面共享同一份 `TodoItem` 数据源，通过不同的过滤条件和渲染方式展示。

#### 三个界面的展示策略

| 界面 | 展示方式 | 查询条件 | 说明 | todo的UI类型 |
|------|----------|----------|------|------|
| **任务池** | 树形结构（可折叠） | `plan_doc_id = X` | 按计划书批量加载所有任务，内存中按 `parent_id` 构建树 | 普通（TodoItem） |
| **任务安排（日历拖拽）** | 平级结构，仅显示父任务 | `parent_id IS NULL AND state = 'pool'` | 子任务不显示，拖拽父任务时子任务自动跟随 | 普通（TodoItem） |
| **每日聚焦** | 树形结构（可折叠） | `scheduled_date = 'YYYY-MM-DD'` | 按日期批量加载，内存中按 `parent_id` 构建树 | 详细（TodoItemDetailed） | 

#### 数据流示意

```
┌─────────────────────────────────────────────────────────────────┐
│                    TodoItem 数据库（单一数据源）                  │
│                                                                 │
│  id | content | parent_id | state | scheduled_date | ...        │
└─────────────────────────────────────────────────────────────────┘
                              │
           ┌──────────────────┼──────────────────┐
           ▼                  ▼                  ▼
    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
    │   任务池     │    │  任务安排    │    │  每日聚焦   │
    │  (树形视图)  │    │ (平级+仅父)  │    │  (树形视图) │
    └─────────────┘    └─────────────┘    └─────────────┘
```

#### 拖拽时的级联更新逻辑

当用户将父任务从任务池拖拽到日历某一天时：

```sql
-- 父任务及其所有子任务同时更新
UPDATE todo_list 
SET scheduled_date = '2026-01-30', state = 'scheduled'
WHERE id = 父任务ID 
   OR parent_id = 父任务ID;
```

#### 前端树形构建流程

1. **一次性查询**：按 `plan_doc_id` 或 `scheduled_date` 批量获取扁平列表
2. **内存中构建**：遍历列表，按 `parent_id` 关系组装成树形结构
3. **递归渲染**：使用 `TodoItemTree` 组件递归展示多层级
