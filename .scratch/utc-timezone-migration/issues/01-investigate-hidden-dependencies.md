# Issue #1: 排查前后端隐性时区依赖并产出指导文档

## Parent

`.scratch/utc-timezone-migration/prd.md`

## What to build

全面排查系统中所有可能受时区变化影响的代码和逻辑，产出一份完整的隐性依赖清单和修改指导文档。

排查方法包括但不限于：
- 代码模式搜索（`datetime.now()`、`date()`、时间字符串比较等）
- 业务逻辑审查（定时任务、统计报表、数据同步等）
- 数据流分析（时间数据在各层之间的传递和转换）
- 边界场景识别（午夜、跨日、时区边界等）

**⚠️ 停止条件**：如果调研发现 UTC + ISO 8601 迁移会给当前项目造成巨大问题（如核心功能完全失效、数据无法恢复、用户体验严重受损），立即停止任务并报告问题。

**产出文档** `docs/guides/utc-migration-hidden-dependencies.md` 应包含：
1. **已发现的隐性依赖清单**（按模块/文件组织）
2. **每个依赖的风险等级**（高/中/低）
3. **修复策略和注意事项**（供后续 agent 参考）
4. **功能失效清单**（UTC 迁移会导致哪些功能暂时失效或需要额外处理，只记录不修改）
5. **测试验证要点**（如何验证修改正确）
6. **可能遗漏的风险点提示**（提醒后续开发者注意）

## Acceptance criteria

- [ ] 已搜索并审查所有包含时间处理的代码文件
- [ ] 已识别所有定时任务的触发时间逻辑和相对时间计算
- [ ] 已识别所有时间范围查询和时间分组逻辑
- [ ] 已识别所有前端时间选择器和日期传递逻辑
- [ ] 已识别所有日志、调试、数据导出中的时间格式假设
- [ ] 已识别所有可能存在的"本地时间"语义假设（如"今天"、"本周"、"午夜"等）
- [ ] 已记录所有因 UTC 迁移可能失效的功能（不修改，只记录）
- [ ] 如果发现重大阻塞问题，已停止任务并报告
- [ ] 产出的文档提供了清晰的修改指导，后续 agent 可以直接参考执行
