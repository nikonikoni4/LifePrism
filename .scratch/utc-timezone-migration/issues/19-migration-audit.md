# Issue #19: 数据迁移结果审核和对比验证

## Parent

`.scratch/utc-timezone-migration/prd.md`

## What to build

独立审核 Issue #16 的数据库迁移结果，对比迁移前后的数据，确保迁移正确无误。

**审核内容**：
1. **数据完整性对比**：
   - 对比迁移前后的记录总数（应该相同）
   - 对比迁移前后的非时间字段（应该完全一致）
   
2. **时间字段迁移验证**：
   - 随机抽样 50-100 条记录
   - 验证每个时间字段是否正确减 8 小时
   - 验证时间格式是否转为 ISO 8601
   - 验证 UTC 旧表的时间字段未被修改

3. **边界场景验证**：
   - 检查 NULL 时间字段是否保持 NULL
   - 检查最早和最晚的时间记录是否正确迁移
   - 检查跨午夜的时间记录（可能导致日期变化）

4. **迁移日志审查**：
   - 确认迁移日志记录完整（表名、字段名、影响行数）
   - 确认所有预期表都已迁移
   - 确认没有意外的错误或警告

**对比方法**：
- 使用备份数据库 `lifewatch_ai - utc-refactor.db`（迁移前）
- 使用测试数据库 `lifewatch_ai.db`（迁移后）
- 编写 SQL 查询或 Python 脚本进行自动对比

**产出**：
- 审核报告 `docs/generated/utc-migration-audit-report.md`
- 包含：抽样结果、边界场景验证、发现的问题（如果有）、审核结论

## Acceptance criteria

- [ ] 已对比迁移前后的记录总数，确认一致
- [ ] 已抽样验证 50-100 条记录的时间字段迁移正确
- [ ] 已验证时间格式转为 ISO 8601
- [ ] 已验证 UTC 旧表未被修改
- [ ] 已验证 NULL 时间字段保持 NULL
- [ ] 已验证边界场景（最早/最晚记录、跨午夜记录）
- [ ] 已审查迁移日志完整性
- [ ] 已产出审核报告
- [ ] 如果发现问题，已报告并建议修复方案
- [ ] 审核通过后，批准进入生产环境迁移
