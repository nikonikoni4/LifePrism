## 1. 分类页面包含什么？

页面包含三个选项卡，顶部分段控件切换：

| 选项卡 | code 中的 tab 名 | 功能 |
|--------|-----------------|------|
| **Category Settings** | `settings` | 管理分类层级（主分类 + 子分类），增删改禁用 |
| **Data Review** | `review` | 审核和修正 AI 分类结果（单条/批量） |
| **Map Cache** | `mapCache` | 管理应用→分类的映射缓存 |

## 2. Category Settings

管理分类层级结构。

#### 核心概念

- **主分类**（Main Category）：顶层分类（如工作/学习、娱乐、其他）
- **子分类**（Sub Category）：主分类下的细分（如"工作/学习"下有编程、学习、计划等）
- 每个主分类有独立颜色，子分类自动生成同色系衍生颜色

#### 系统默认分类

系统初始提供 5 个主分类：**工作**、**学习**、**娱乐**、**泛娱乐**、**其他**。每个主分类下可设置任意子分类。

#### 操作

| 操作 | 方法 | 影响 |
|------|------|------|
| **添加主分类** | 点击 `+ Add New Category` | 创建新的主分类 |
| **添加子分类** | 选中主分类 → 在输入框输入 → 点击 Add | 添加到当前主分类下 |
| **修改名称** | 选中分类 → 点击编辑按钮 | 自动保存 |
| **禁用分类** | 选中分类 → 点击禁用按钮（有确认弹窗） | ⚠️ 见下方 |
| **启用分类** | 选中已禁用的分类 → 点击启用按钮 | ⚠️ 见下方 |
| **删除分类** | 选中分类 → 点击删除按钮（有确认弹窗） | ⚠️ 危险操作 |

#### 禁用分类

禁用后效果：
- AI **不再使用该分类**对新数据进行分类
- **历史数据保留**，仍可正常显示
- **Map Cache 中该分类的缓存被同步禁用**（该分类下的应用回到待分类状态）
- 已绑定该分类的 **Goal 不再纳入分类流程**

禁用前会弹出确认提示。

#### 启用分类

启用分类后，AI 恢复使用该分类进行自动归类，同时**自动恢复该分类下之前被禁用的缓存记录**。

**冲突处理机制：** 如果分类禁用期间，原本属于该分类的应用被 AI 归类到了其他类别并产生了新缓存，启用操作会**自动删除禁用期间产生的新缓存，优先恢复原有的分类设置**。

时间轴示例：
1. **T1（正常）**：App A 被归类为「工作」（缓存有效）
2. **T2（禁用）**：用户禁用「工作」分类（T1 缓存失效）
3. **T3（运行）**：App A 再次运行，因「工作」禁用，AI 将其归类为「其他」（产生新缓存）
4. **T4（恢复）**：用户重新启用「工作」分类 → **系统删除 T3 的「其他」缓存，恢复 T1 的「工作」缓存**

#### 删除分类

删除后该分类下所有关联的分类信息被**同步删除**，不可恢复（需重新同步数据）。删除前会弹出确认提示。

## 3. Data Review

审核和修正 AI 对单条活动记录的自动分类。

#### 单条修改

点击记录 → 在下拉菜单中选择正确的主分类和子分类 → 自动保存。

#### 批量修改

勾选多条记录 → 批量操作按钮 → 批量修改分类或批量删除。

#### ⚠️ 重要说明

**Data Review 修改只影响当前选中的单条记录。** 如果同一应用/标题后续仍会分错，应该用 **Map Cache** 修改映射关系（影响所有匹配数据）。

## 4. Map Cache（映射缓存）

管理"应用/窗口标题 → 分类"的映射关系。这是 AI 分类流程的最高优先级步骤。

### 为什么需要 Map Cache？

AI 分类流程优先级：
```
① Map Cache 命中（最快，零成本）
→ ② Goal 匹配（目标绑定的分类）
→ ③ AI 分类（调用 LLM，消耗 Token）
```

AI 分类一次后结果自动写入 Map Cache，下次相同应用直接使用缓存，不需要再次调用 AI。

### 单用途 vs 多用途应用

这是 Map Cache 中最核心的概念，由字段 `is_multipurpose_app` 控制匹配策略。**理解两者的区别，是正确修正分类错误的关键。**

**核心区别：**
- **单用途**：按 **App** 分类。修改某个 App 的分类后，该 App **下所有的 Title 都会变为这个类型**。例如 VS Code 编辑器，无论打开什么文档，其行为都被归为一类。
- **多用途**：按 **App + Title** 组合分类。不同的 Title 可以分别设置为不同的分类。例如浏览器，github.com 归为工作，bilibili.com 归为娱乐。

| 特性 | 单用途 | 多用途 |
|------|--------|--------|
| 匹配规则 | **app**（应用名） | **app + title**（应用名+窗口标题） |
| 修改分类影响 | 修改后该应用**所有 title 记录的**分类都跟着改变 | 只影响该应用+该窗口标题这一条 |
| 场景示例 | VS Code → 始终归为"工作/学习—编程" | Chrome + github.com → 工作；Chrome + bilibili → 娱乐 |

**配置多用途应用：** 在 **Settings → 分类逻辑 → 多用途应用列表**（字段 `multi_purpose_app_names`）中添加你认为不属于单用途的应用。默认预设了浏览器类应用。

### Map Cache 记录字段

| 字段 | type | 说明 |
|------|------|------|
| `app` | string | 应用名 |
| `title` | string | 窗口标题 |
| `is_multipurpose_app` | boolean | 是否多用途 |
| `category_id` / `sub_category_id` | string | 关联的分类 ID |
| `link_to_goal_id` | string \| null | 关联的目标 ID |
| `app_description` | string \| null | 应用描述（用于 AI 分类参考） |
| `title_analysis` | string \| null | 标题分析（用于 AI 分类参考） |
| `state` | number | 缓存状态（1=启用，0=禁用） |

### 操作

#### 修改映射分类

1. 进入 **Map Cache** 选项卡
2. 在列表中搜索定位到目标应用
3. 修改 `category_id` 和 `sub_category_id`
4. 确认保存

**后续新数据**自动使用修改后的分类。

#### 同步到日志 (updateLogsByCache)

**作用：** 将 Map Cache 的修改应用到所有匹配的**历史记录**。

**操作：** 修改 Map Cache 后 → 点击"同步到日志" → 系统更新所有历史记录的分类

**API：** `POST /api/v2/activity/manage/logs/update-by-cache`

**参数：** `app`, `title`, `is_multipurpose_app`, `category_id`, `sub_category_id`, `goal_id`, `start_date`, `end_date`

#### Link to Goal（关联目标）

**作用：** 将某应用的缓存记录关联到指定 Goal，使其使用时间被统计到该目标中。

**操作：**
1. Map Cache 中找到目标应用
2. 编辑 → 设置 `link_to_goal_id`
3. 确认 → 重新同步数据

**规则：**
- 单用途应用：一个 app 只能绑定一个 goal
- 多用途应用：通过不同 title 可绑定多个 goal
- 浏览器当前是唯一推荐设为多用途的应用

**分时间段绑定不同 Goal：**
若同一应用在不同时间段服务于不同目标（如 VS Code 1-5 号做项目 A，6-10 号做项目 B）：
1. 1-5 号将 VS Code 绑定到 Goal A，同步数据
2. 6-10 号将绑定改为 Goal B，同步数据
3. 统计时时间分别计入 A 和 B

## 常见操作

### AI 分类错了，怎么修正？

| 场景 | 方法 | 位置 |
|------|------|------|
| **某条记录错了** | 单条修改 | Timeline 右侧面板 或 Data Review |
| **某应用总是分错** | 修改 Map Cache 映射 → 同步到日志 | **Map Cache**（推荐） |
| **某分类下所有应用都要修改** | 批量修改 | Data Review（批量模式） |

### 什么时候用 Data Review，什么时候用 Map Cache？

- **单条特定记录错误** → Data Review
- **某应用所有记录都错了** → Map Cache（一次修改影响所有）
- **某个分类想彻底改** → Map Cache + 同步到日志

### 找不到编辑/删除按钮？

Map Cache 列表的编辑/删除按钮可能因屏幕宽度不足被隐藏。缩小浏览器缩放比例或最大化窗口即可看到。
