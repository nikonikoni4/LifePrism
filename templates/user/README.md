# 个人成长与心理建模体系

本目录采用四层架构组织用户数据，层与层之间单向流动：

```
原始数据层 -> 叙事层 -> 心理建模层 -> 心智进化层
```

核心设计原则：每一层职责单一，AI 写入时无需判断边界歧义。下层内容必须能追溯到上层的具体来源。

---

## 文档设计原则

所有文档遵循以下三条原则：

**1. 明确的写入与读取时机**
每个文档须说明何时写入（触发条件）、何时读取（使用场景），避免 AI 在无明确触发时随意写入。

**2. 单一职责**
AI 写入时对任意一条内容只有唯一的归属判断，无需在多个文件之间权衡。

**3. 渐进式披露读取**
每个文档设置「摘要 + 内容」两层结构，AI 优先读取 frontmatter 中的 summary，仅在 summary 不足以回答当前问题时才读取正文。
> 占位说明：当前各文档尚未写入实际数据，渐进式披露的具体格式规范待首批数据写入后补充。

### Frontmatter 规范

每个文档必须包含以下 frontmatter：

```yaml
---
name: 文档名称
summary: 一句话描述当前文档核心内容（摘要层，供 AI 优先读取）
read_priority: high | on_demand   # high = 对话初始化时主动加载；on_demand = 触发条件满足时才读取
last_updated: YYYY-MM-DD
last_event: 触发本次更新的事件简述（一句话）
---
```

当前每个文档的描述字段：
- **存放内容**：该文档存储什么
- **单一职责**：该文档唯一的建模目的
- **写入权限**：AI 自主写入 / 需用户授权
- **写入时机**：触发写入的条件
- **读取时机**：触发读取的场景
- **关键规则**：写入时必须遵守的约束
- **禁止写入**：明确排除的内容及其正确归属

## 用户速览文档 user.md

核心原则：标签式存储，服务于 AI 在对话开始时快速建立用户上下文，不做深度分析。

### user.md
- **存放内容**：基本信息（职业、专业）、核心知识图谱（当前正在研究的领域/内容）、核心偏好（AI 回答风格、沟通偏好）、习惯与禁忌
- **单一职责**：提供用户的快速索引，让 AI 无需读取其他文档即可了解用户基本轮廓
- **写入权限**：用户主动告知时 AI 可写入；涉及核心偏好变更时需用户确认
- **写入时机**：用户主动告知个人信息时；核心偏好发生变化时
- **读取时机**：每次对话开始时优先读取，作为上下文初始化
- **关键规则**：内容以标签/简短短语为主，不展开叙述；深度信息由其他文档承载
- **禁止写入**：心理分析结论、成长叙事、行为数据 -> 分别归入对应的建模层和原始数据层

## 第一层：原始数据层 raw_data/

核心原则：客观提炼与记录，严禁包含主观评价或推断。

### behavior.md
- **存放内容**：以天为单位的用户行为语义记录，来源包含三类：
  1. 电脑分类使用数据（学习/工作/娱乐等时长统计）、习惯打卡记录、计划完成情况
  2. 日记中提炼的当天客观事件
  3. 当天聊天记录（含 claude.ai、Claude Code、Codex 等）中提炼的有语义价值的行为内容
- **单一职责**：从行为角度记录用户每天真正在做什么，服务于两个用途：① 心理分析（判断行为与价值观/目标是否对应）；② 用户查询（「我最近在做什么」）
- **写入权限**：Agent 每日定时写入
- **写入时机**：
  1. 每天定时增量写入，起始日期从 diary 表查询（条件：word_count > 0）
  2. 检查 diary.updated_at 是否为今天，若是则重新读取日记同步更新
  3. 聊天数据写入流程（见下方）
- **聊天数据写入流程**：
  - Step 1：对当天所有 session（含当天有更新的历史 session）进行 session 级别总结，输出每个 session 的对话主题（一句话语义浓缩）+ 用户消息总字数
  - Step 2：过滤——同时满足以下两条则丢弃：① 用户消息字数少；② 对话主题不涉及心理层面（情绪/价值观/个人成长）
  - Step 3：将保留的主题合并写入，格式示例：「深度学习了 [主题]」、「推进了 [项目/任务]」、「讨论了 [心理/个人层面话题]」
- **读取时机**：
  1. 用户询问最近在做什么 / 总结最近行为时
  2. 心理建模分析时（作为行为层输入）
  3. 其他场景待定（占位）
- **禁止写入**：对行为的主观评价、对用户状态的推断、纯知识性/技术性问答内容

### classify_preference.md
- **存放内容**：用户对电脑使用数据分类方式的偏好设置，例如将某类应用归入「学习」而非「娱乐」的自定义规则
- **单一职责**：记录用户对行为数据分类的个性化偏好，供前端数据处理时参照
- **写入权限**：仅在用户主动确认时写入，AI 不主动推断写入
- **写入时机**：用户在前端修改数据分类并确认「纳入偏好设置」时
- **读取时机**：前端展示或处理电脑使用数据时，作为分类规则参照
- **禁止写入**：行为数据本身、对分类习惯的心理分析

## 第二层：叙事层 narrative/

核心原则：半客观记录，侧重故事完整性，保留事件发生时的情感体验，移除用户对事件的评价与归因。

### growth_story.md
- **存放内容**：用户主动描述的人生经历、关键事件、转折节点；事件发生时用户的情感体验（"那时我很害怕"）；讲述时当下的情绪反应标记（供后续流入 emotion.md）
- **单一职责**：保存用户视角的成长叙事，作为心理建模的原始素材
- **写入权限**：AI 自主写入
- **写入时机**：用户主动讲述成长经历、关键事件时，AI 判断为新增内容后写入
- **读取时机**：
  1. 用户聊到过往经历时（查重，避免重复写入）
  2. AI 执行心理建模更新前（作为来源依据）
- **禁止写入**：用户对事件的评价与归因（"这让我变得不自信"）-> 归入 cognition.md
- **与 growth_insights.md 的区别**：本文件是输入（用户说了什么），growth_insights.md 是输出（建模分析出了什么变化）

## 第三层：心理建模层 psychological_model/

核心原则：将「理想的我」与「真实的我」分离，提取高浓缩的语义内容。所有条目必须能追溯到叙事层或原始数据层的具体来源。

### ideal_self/ 层权限规则

> **AI 对 ideal_self/ 下所有文件无自主写入权限。** AI 可根据对话内容提出写入建议，但必须经用户明确授权后才能执行写入或修改。

### ideal_self/creed.md
- **存放内容**：用户手动定义的个人原则与行为纲领
- **单一职责**：记录用户显式承诺的「我要怎么活」
- **写入权限**：仅用户授权后 AI 可写入
- **写入时机**：用户明确表达个人原则时，经授权写入
- **读取时机**：
  1. 执行矛盾分析时
  2. 用户谈到自我要求/原则时（判断是否需要更新）
- **禁止写入**：由 AI 推断的价值观 -> 归入 values.md

### ideal_self/values.md
- **存放内容**：核心价值观、对理想生活和理想自我的期待、对理想认知方式的期待（如「希望自己能自我慈悲」）、基于价值做出的承诺
- **单一职责**：描述「希望的我」——用户想成为什么、想过什么样的生活
- **写入权限**：仅用户授权后 AI 可写入
- **写入时机**：用户表达对理想生活、理想自我的期待时，经授权写入
- **读取时机**：
  1. 执行矛盾分析时
  2. 用户谈到想成为什么样的人时（判断是否需要更新）
- **禁止写入**：用户当下真实的认知和情绪反应

### real_self/cognition.md
- **存放内容**：用户当下真实的核心信念、归因方式、认知扭曲模式；用户对过往事件的评价与归因（反映当下认知水平）
- **单一职责**：描述「真实的我（认知维度）」——用户实际上怎么想、怎么解读世界
- **写入权限**：AI 自主写入
- **写入时机**：AI 从具体事件中观察到稳定的认知反应模式时写入
- **读取时机**：
  1. 构建/更新 cog_emo_interface 时
  2. 执行矛盾分析时
  3. 用户讨论某个困扰/问题时
- **关键规则**：所有条目必须有具体事件来源，只能从实际反应中反推，不能来自用户的自我描述
- **禁止写入**：用户了解的心理学知识、用户希望自己持有的认知方式（后者归入 values.md）

### real_self/emotion.md
- **存放内容**：用户的情绪基线、当下生活情境中的情绪触发模式与反应、实际使用的情绪调节策略；讲述过往时当下爆发的情绪反应
- **单一职责**：描述「真实的我（情绪维度）」——用户实际上怎么感受、如何应对情绪
- **写入权限**：AI 自主写入
- **写入时机**：AI 从具体事件中观察到稳定的情绪触发模式时写入
- **读取时机**：
  1. 构建/更新 cog_emo_interface 时
  2. 执行矛盾分析时
  3. 用户讨论某个困扰/问题时
- **关键规则**：必须有事件来源；故事里「当时」的历史情绪留在 growth_story.md，不写入此处
- **禁止写入**：用户希望自己拥有的情绪状态

### real_self/cog_emo_interface.md
- **存放内容**：具体情境中认知如何触发情绪（评价链）、情绪如何反向扭曲认知（情绪化推理）的闭环链路
- **单一职责**：描述认知与情绪在具体情境中如何串联成闭环，用语义锚点引用 cognition.md 和 emotion.md 的内容，不重复记录内容本身
- **写入权限**：AI 自主写入
- **写入时机**：cognition.md 或 emotion.md 有新增/更新时，AI 判断是否形成新的闭环链路后写入
- **读取时机**：
  1. 执行矛盾分析时
  2. 用户讨论某个困扰时
- **禁止写入**：独立的认知条目或情绪条目（归属各自文件）

### contradictions/contradictions.md
- **存放内容**：「真实的我」（real_self）与「理想的我」（ideal_self）之间的结构性张力，每条矛盾包含：
  - 表层冲突：行为与目标的直接冲突（客观描述）
  - 深层机制：基于 ACT 框架的解释（认知融合、经验性回避、概念化自我的僵化）
- **单一职责**：识别并描述真实自我与理想自我之间的张力结构，直接对应 ACT 干预靶点
- **写入权限**：AI 自主写入
- **写入时机**：ideal_self、cognition、emotion、cog_emo_interface 任意一层发生实质性更新时，AI 重新评估并写入
- **读取时机**：
  1. 用户讨论困扰/逃避行为时
  2. 用户主动寻求心理洞察时
  3. 更新 growth_insights 时
- **禁止写入**：治疗方案或行动建议
- **条目格式**：
  ```
  ## [矛盾名称]
  表层冲突：...
  深层机制：
  - 认知融合：...
  - 经验性回避：...
  ```

## 第四层：心智进化层 growth_insights.md

核心原则：跨越所有层次，记录整体心智模型的演化轨迹。

### growth_insights.md
- **存放内容**：用户在认知、情绪、价值层面发生的可观察转变；认知边界的扩展；深刻见解的涌现；心理模型的重塑记录
- **单一职责**：记录整体心智模型随时间演化的变化日志，是所有建模层的版本历史汇总
- **写入权限**：AI 自主写入
- **写入时机**：cognition.md / emotion.md / ideal_self / contradictions 任意一层发生实质性更新时，变化摘要同步写入
- **读取时机**：
  1. 用户主动回顾自己的成长/变化时
  2. 长期对话后的阶段性总结时
  3. 更新任意建模层之前（参照历史变化，避免写入退步内容）
- **禁止写入**：用户的原始叙述、未经建模验证的变化声明
- **与 growth_story.md 的区别**：growth_story.md 是用户说了什么（输入），本文件是建模分析出了什么变化（输出）
